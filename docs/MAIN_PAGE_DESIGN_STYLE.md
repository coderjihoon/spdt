# SPDT 메인 페이지 디자인 스타일

이 문서는 메인 페이지(`/`)의 현재 구현을 기준으로 정리한 디자인 가이드다. 새 화면을 만들거나 기존 화면을 수정할 때 메인 페이지와 같은 인상을 유지하기 위한 기준으로 사용한다.

## 1. 디자인 방향

메인 페이지는 **밝고 정돈된 전략 스튜디오**의 인상을 지향한다.

- 흰 배경과 넓은 여백을 기본으로 사용한다.
- 색상은 중립적인 슬레이트 계열을 중심으로 하고, 브랜드 블루는 CTA와 핵심 표시 요소에만 사용한다.
- 제목은 크고 단단하게, 본문은 차분하고 읽기 쉽게 구성한다.
- 장식보다 정보의 순서, 카드의 밀도, 정렬과 간격으로 완성도를 만든다.
- 실제 이미지보다 추상화된 UI 프리뷰와 구조도를 사용해 기획·전략 서비스의 성격을 보여준다.
- 지나치게 굵은 글자, 강한 그림자, 과도한 그라데이션은 사용하지 않는다.

## 2. 컬러 시스템

### 브랜드 팔레트: Ocean Breeze

로고·전체 액센트 컬러의 원본 팔레트. 5단계 모두 파랑 한 색상 안에서의 명도 변화다.

| 단계 | HEX | RGB | 비고 |
|---|---|---|---|
| 900 | `#042E7B` | `4, 46, 123` | 가장 어두운 네이비 |
| 700 | `#004EE0` | `0, 78, 224` | 딥 블루 |
| 500 | `#1883FF` | `24, 131, 255` | 메인 브랜드 블루 |
| 300 | `#99CAFF` | `153, 202, 255` | 라이트 블루 |
| 100 | `#E3F2FF` | `227, 242, 255` | 가장 옅은 블루 틴트 |

### 핵심 색상 (역할 매핑)

| 역할 | 값 | 사용처 |
|---|---|---|
| Primary | `#004EE0` (Ocean Breeze 700) | 주요 CTA, 번호 배지, 강조 카드, 포인트 도형 |
| Primary hover | `#042E7B` (Ocean Breeze 900) | Primary 버튼 hover |
| Primary light | `#1883FF` (Ocean Breeze 500) | 프로그레스바, 포커스 링, 그라데이션 밝은 톤 |
| Primary light surface | `#99CAFF`, `#E3F2FF` (Ocean Breeze 300/100) | 점선 보더, 연한 hover 배경, 어두운 배경 위 라벨 |
| Page background | `#ffffff` | 페이지 기본 배경 |
| Soft surface | `#f7f7fb` | 카드와 내부 패널 배경 |
| Secondary surface | `#f1f3f9` | 폼 진행 상태 배너, FAQ 아이콘 칩 등 낮은 강조 배경 |
| Subtle border | `#ececf4` | 카드 ring과 내부 경계선 |

### 텍스트와 중립색

| 역할 | Tailwind | 값 |
|---|---|---|
| 가장 강한 제목 | `slate-950` | `#020617` |
| 제목·로고 | `slate-900` | `#0f172a` |
| 보조 강조 텍스트 | `slate-700` | `#334155` |
| 본문 | `slate-600` | `#475569` |
| 라벨·설명 | `slate-500` | `#64748b` |
| 비활성·메타 정보 | `slate-400` | `#94a3b8` |
| 장식 점 | `slate-300` | `#cbd5e1` |
| 가벼운 테두리 | `slate-200`, `slate-100` | `#e2e8f0`, `#f1f5f9` |

### 사용 원칙

- 한 화면에서 Primary의 면적을 작게 유지한다. 기본적으로 버튼, 작은 배지, 선택 카드에만 쓴다.
- 일반 섹션은 흰 배경을 유지하고 카드로만 면을 구분한다.
- 흰색 위의 텍스트는 `slate-950`부터 `slate-500` 사이에서 위계를 만든다.
- 컬러 카드에서는 흰색의 불투명도(`white/55`, `white/75`, `white/86`)로 위계를 만든다.
- 강한 그라데이션은 마지막 CTA처럼 전환을 집중시키는 구간에만 사용한다.

## 3. 타이포그래피

### 글꼴

전역 글꼴 스택은 다음 순서다.

```css
"SUIT Variable", "Pretendard Variable", "Pretendard", "Noto Sans KR",
system-ui, -apple-system, BlinkMacSystemFont, sans-serif
```

프로젝트에서 웹폰트 파일을 직접 불러오지는 않는다. 사용자 환경에 설치된 글꼴 또는 시스템 폰트로 대체된다.

### 타입 스케일

| 용도 | 모바일 | 태블릿 | 데스크톱 | 주요 속성 |
|---|---:|---:|---:|---|
| Hero 제목 | `40px` | `56px` | `68px` | `500`, line-height `1.02`, tracking `-0.055em` |
| 섹션 제목 | `38px` | `44px` | `52px` | `500`, line-height `1.05~1.1`, tracking `-0.05em` |
| 카드 제목 | `20~24px` | 동일 | 동일 | `500`, tracking `-0.03~-0.04em` |
| Hero 본문 | `17px` | `17px` | `19px` | line-height `1.65` |
| 기본 본문 | `16px` | 동일 | 동일 | line-height `28px` |
| 보조 본문 | `14~15px` | 동일 | 동일 | line-height `24~32px` |
| 영문 섹션 라벨 | `14px` | 동일 | 동일 | `500`, tracking `0.18em` |
| 버튼 | `12px` | 동일 | 동일 | `500` |

### 사용 원칙

- 제목은 기본적으로 `font-medium`을 사용한다. 과도한 bold는 피한다.
- 큰 제목에는 음수 자간을 적용해 글자 덩어리를 단단하게 만든다.
- 영문 라벨과 단계 표시는 넓은 양수 자간으로 제목과 대비시킨다.
- 본문 한 줄은 지나치게 길어지지 않도록 `max-w`를 지정한다.
- 핵심 문장은 `[text-wrap:balance]` 또는 제한된 너비를 사용해 줄바꿈을 통제한다.

## 4. 레이아웃과 반응형

### 기본 컨테이너

```text
페이지 좌우 여백: 16px → sm 24px → lg 40px
콘텐츠 최대 너비: 1280px
일반 섹션 상하 여백: 56px → lg 96px
```

- 모든 주요 섹션은 `mx-auto max-w-[1280px]` 축에 맞춘다.
- 모바일 우선으로 작성하며 Tailwind 기본 breakpoint를 사용한다.
- 모바일에서는 대부분 1열, `md` 또는 `lg`부터 2~3열로 전환한다.
- 텍스트와 시각 요소의 2열 구간은 대체로 `0.9fr / 1.1fr` 비율을 사용한다.
- 카드 간격은 보통 `16~20px`, 큰 콘텐츠 블록 간격은 `40~48px`를 사용한다.

### 대표 그리드

- 문제 카드: 모바일 1열, `md` 2열, `lg` 3열
- 진단서 미리보기(항목별 진단): 모바일 1열, `sm` 2열
- 진단 항목(다섯 기준): 설명과 목록을 `lg`부터 `0.9fr/1.1fr` 2열, 목록은 세로 1열
- 전달 예시: 모바일 1열, `lg` 2열 카드
- 프로세스: 설명과 타임라인을 `lg`부터 2열, 타임라인 자체는 세로 1열
- 신뢰(Trust): 모바일 1열(구분선), `lg` 3열(구분선을 세로선으로 전환)
- 증빙(Proof): 통계 3열(`sm`부터), 후기 카드는 `sm` 2열 + 창업자 카드
- FAQ: 소개와 질문 목록을 `lg`부터 `0.9fr/1.1fr` 2열로 분리

## 5. 공통 컴포넌트 스타일

### 섹션 헤더

1. 영문 라벨: `14px`, `font-medium`, `tracking-[0.18em]`, `slate-500`
2. 제목: 위쪽 `12px`, 반응형 `38/44/52px`, `slate-950`
3. 설명: 위쪽 `16~20px`, `16px/28px`, `slate-600`

제목 블록 너비는 보통 `720~780px`로 제한한다.

### 카드

기본 카드 스타일:

```text
배경: #f7f7fb 또는 white
모서리: 20px
테두리: 1px inset ring #ececf4
내부 여백: 24~40px
그림자: 기본적으로 없음
```

- 카드 안의 작은 패널은 `14~16px` 라운드를 사용한다.
- 아이콘이나 번호 박스는 `10~12px` 라운드로 더 작게 만든다.
- 그림자는 Hero의 떠 있는 UI 카드에서만 매우 약하게 사용한다.
- 카드의 위계는 그림자보다 배경색, ring, 내부 여백으로 표현한다.

### 버튼

| 종류 | 스타일 |
|---|---|
| Primary | 블루(`#004EE0`) 배경, 흰 텍스트, hover 시 더 어두운 블루(`#042E7B`) |
| Text link | 밑줄과 `underline-offset-2~4`; 진단서 예시 보기, 이메일 등 보조 이동에 사용 |

메인 페이지에는 현재 흰 배경 Secondary/Inverse 버튼이 없다. `#f1f3f9`는 버튼이 아니라 폼 진행 상태 배너, FAQ `+` 아이콘 칩 같은 낮은 강조 요소의 배경으로만 쓰인다. (Inverse 스타일은 `/report/[slug]` 결과 페이지의 상담 버튼에서만 쓰인다.)

- 기본 라운드는 `10~12px`이다.
- 주요 Hero 버튼은 `px-7 py-4`, 일반 버튼은 `px-4~6 py-2~3.5`를 사용한다.
- 전환은 기본 `transition`만 사용하며 크기 변화나 튀는 효과는 넣지 않는다.

### 브랜드 표시

- 헤더·푸터 모두 `public/logo.png`(파랑 "SP" + 검정 "DT" 워드마크) 이미지를 `next/image`로 렌더링해 통일했다. 원본 비율은 662:298이며, 헤더는 높이 `28px`(`h-7`), 푸터는 조금 더 큰 `32px`(`h-8`)를 쓴다.
- 로고 옆에는 `상페닥터 · 무료 진단`(헤더) / `상페닥터 · 무료 상세페이지 진단`(푸터) 부제를 `12px`, `slate-500`으로 둔다. 헤더는 `sm` 이상에서만 노출한다.
- 로고 이미지에 이미 "SPDT" 워드마크가 포함돼 있어, 별도의 `SPDT` 텍스트 로고나 원형 `SP` 배지는 더 이상 쓰지 않는다.

## 6. 시각 효과와 모션

- Hero 배경에는 중앙 확산형 블루 radial gradient를 낮은 불투명도로 사용한다.
- Hero UI 카드 그림자는 `rgba(15,23,42,0.05~0.06)` 수준으로 제한한다.
- 신청 폼(하단 CTA) 패널만 radial gradient 2개 + linear gradient를 조합한 블루 그라데이션 배경을 쓴다.
- 신뢰(Trust) 섹션은 marquee가 아니라 정적인 3분할 카드 목록이다(`animate-marquee`는 더 이상 메인 페이지에서 쓰이지 않는다. 레거시 `/about` 페이지에서만 여전히 사용).
- FAQ는 네이티브 `<details>/<summary>`로 구현하며 `+` 아이콘이 열릴 때 45도 회전한다(`group-open:rotate-45`).
- 앵커 이동(`#report-preview`, `#diagnosis-form` 등)은 컴포넌트 단위가 아니라 `html { scroll-behavior: smooth }` 전역 설정으로 부드럽게 스크롤된다.
- `prefers-reduced-motion: reduce`에서는 `scroll-behavior`를 `auto`로 되돌린다(`app/globals.css`).

## 7. 페이지 구성과 역할

`app/page.tsx` 기준 실제 섹션 순서(컴포넌트는 모두 `components/apply/*`):

| 순서 | 섹션 | 컴포넌트 | 역할 |
|---:|---|---|---|
| 1 | Promo + Header | `Header` | 무료 진단 유입 배너, 로고, 주요 탐색, 모바일 하단 고정 CTA |
| 2 | Hero | `Hero` | 가치 제안 + URL/이미지 신청 폼(2택), 오른쪽 진단 리포트 미리보기 카드 |
| 3 | 진단서 미리보기 | `ReportPreviewSection` | 실제 `/report/[slug]` 결과와 동일한 형식의 SAMPLE 리포트 |
| 4 | 증빙 | `ProofSection` | 진단 건수 등 통계, 고객 후기, 창업자 소개 |
| 5 | Problem | `ProblemSection` | 고객이 겪는 문제를 카드로 명확화 |
| 6 | Diagnosis | `DiagnosisSection` | 5가지 진단 기준 나열 |
| 7 | Example | `ExampleSection` | 문제·이유·개선 방향 케이스 카드 |
| 8 | Process | `ProcessSection` | 진행 과정 타임라인 |
| 9 | Trust | `TrustSection` | 어두운 패널의 3분할 신뢰 포인트 |
| 10 | FAQ | `FAQSection` | 구매 전 질문 해소 |
| 11 | 신청 폼 | `FormSection` | 무료 진단 최종 신청(id=`diagnosis-form`) |
| 12 | Footer | `Footer` | 브랜드 설명, 메뉴, 연락처 |

텍스트 콘텐츠와 반복 데이터의 기준은 `data/apply.ts`, 섹션 순서의 기준은 `app/page.tsx`다. (레거시 `/about` 페이지는 `data/site.ts`와 `components/*.tsx` 최상위 컴포넌트를 그대로 쓰며 이 가이드의 적용 대상이 아니다.)

## 8. 이미지와 디자인 리소스

- `public/logo.png`: 헤더 워드마크 이미지(파랑 "SP" + 검정 "DT", 662×298). `next/image`로 렌더링하며 현재 메인 페이지의 유일한 이미지 에셋이다.
- Hero의 진단 리포트 미리보기 카드, `ReportPreviewSection`의 SAMPLE 리포트는 실제 이미지가 아니라 HTML/CSS로 만든 추상 UI 프리뷰다.
- 과거 화면 캡처는 `docs/spdt-*.png`에 보관되어 있다(레거시 `/about` 버전 기준이라 현재 메인 페이지와는 다르다).
- 최초 참고 디자인 분석은 `docs/reference/REFERENCE_WEDGE_ANALYSIS.md`에 있다.
- 새 이미지를 추가할 경우에도 텍스트 위계를 방해하지 않는 낮은 채도와 단순한 구도를 우선한다.

## 9. 적용 체크리스트

- 콘텐츠가 `1280px` 컨테이너 축에 정렬되는가?
- 제목이 `font-medium`과 타이트한 자간을 유지하는가?
- 본문은 `slate-600`, 보조 정보는 `slate-500/400`으로 구분되는가?
- Primary 색상이 핵심 CTA와 강조 요소에만 쓰였는가?
- 카드가 `20px` 라운드, 연한 배경, 얇은 inset ring을 따르는가?
- 섹션 사이에 모바일 `56px`, 데스크톱 `96px` 수준의 여백이 있는가?
- 모바일에서 1열로 자연스럽게 읽히고 가로 스크롤이 생기지 않는가?
- 모션 없이도 정보와 기능을 이해할 수 있는가?
