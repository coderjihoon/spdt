# 네이버 자동 수집 검증 상태

검증일: 2026-10-05 KST

## 완료 기준

고객이 히어로에서 상품 URL을 제출하면 운영자 개인 컴퓨터가 꺼진 상태에서도
상세 본문의 이미지와 텍스트를 화면 순서대로 수집하고 보고서를 생성해야 한다.
운영자의 상품별 조작이나 네이버 계정 쿠키·비밀번호·세션의 서버 전송에 의존하지 않는다.

**현재 이 기준은 미충족이다.** Chrome 확장 프로그램 경로의 성공은 서버 독립 실행의 증거가 아니다.

## 확인한 근거

| 경로 | 실제 관측 | 결론 |
| --- | --- | --- |
| 운영자 Chrome 확장 프로그램 | 피쥬키 신청에서 수집·보고서 생성·이메일 전송까지 확인 | 운영자 Chrome 실행 및 로그인 유지 필요 |
| 네이버 상세 API 직접 요청 | 기존 Apify 상품 식별자를 사용한 요청에 HTTP 429 | 본문 수집 실패. 모든 상품의 불가능을 증명하지는 않음 |
| Apify 기존 성공 결과 | `storeDetail.detailContents`에 `editorType: SEONE`만 존재 | 해당 결과는 상세 본문 수집 증거가 아님. 상품 대표 이미지로 대체 진단해서는 안 됨 |
| Bright Data 네이버 전용 데이터셋 | 피쥬키 URL 실행에 HTTP 400, `Customer is not active` | 계정 활성화 전 본문 수집 가능 여부 미검증 |
| Browserless | 실행 요청에 HTTP 401, 무료 사용량 소진 메시지 | 실제 네이버 접근 여부 미검증 |
| Cloudflare Browser Run `/content` | 피쥬키 URL 요청에 HTTP 200 및 `success: true`, 그러나 HTML 제목은 `[에러] 에러페이지 - 시스템오류`, `se-main-container` 없음 | 전송 성공과 수집 성공을 구분해야 함. 해당 요청은 본문 수집 실패 |
| Apify 내부 한국 주거용 프록시 | 비공개 시험 작업에서 기존 상품의 상세 API 요청에 HTTP 429 | 외부 프록시 연결 제한을 피해도 본문 수집 실패 |
| Apify 원격 Chromium + 한국 주거용 프록시 | 피쥬키 URL 응답 HTTP 429, 제목 `[에러] 에러페이지 - 시스템오류`, 상세 컨테이너 없음 | 이 환경의 원격 브라우저도 본문 수집 실패 |
| Syphoon 네이버 상품 HTML API | 피쥬키 URL에 HTTP 200, 제목 `Sign in - NAVER`, 상세 컨테이너와 사전 로드된 상품 상태 없음 | HTTP 성공이어도 상품 본문이 아니므로 사용 불가 |
| Syphoon 범용 JS 렌더링 API | 피쥬키 URL에 HTTP 200, 제목 `Sign in - NAVER`, 상세 컨테이너 없음 | JS 렌더링을 켜도 본문 수집 실패 |
| Syphoon 네이버 상세 API 요청 | 첫 요청 60초 시간 초과, 재시도 HTTP 500, 상세 본문 없음 | 이 API 경로로 본문 수집 미검증 |

Cloudflare 응답과 Apify 표본은 로컬 `output/naver-server-probe/`에 저장했다.
공급자 테스트에는 운영자 Chrome의 네이버 세션을 전달하지 않았다.
이번 검증으로 운영 배포나 기존 일반 쇼핑몰 캡처 흐름을 변경하지 않았다.

Apify 내부 검증용 비공개 Actor 소스는 `scripts/apify-nav-probe/`에 있다.
Syphoon은 네이버 상품 HTML과 공개 API 요청을 제공한다고 문서화하고 있으며
무료 월 100회 요금제를 표시한다. 제공받은 API 키로 실측했지만 위와 같이
피쥬키 상세 본문은 확인하지 못했다. 로그인 화면을 상품으로 오인하거나
이 서비스를 운영 수집기로 채택하지 않는다.

## 다음 진행 조건

1. 실제 판매자 상세 본문까지 반환하는 서버 수집 서비스를 실증한다. Bright Data 계정은 비활성이고, Syphoon 무료 계정은 피쥬키에서 로그인 화면을 반환했다. 결제·요금제 변경은 실행하지 않았다.
2. 실제 URL로 판매자 상세 본문의 텍스트와 이미지가 반환되는지 검증한다. 대표 이미지·상품 메타데이터만 반환하면 채택하지 않는다.
3. 검증된 수집 방식을 서버 작업 대기열에 연결한다. 공급자 작업 ID, 상태 조회, 재시도, 시간 초과, 중복 완료 방지 및 본문 검증이 필요하다.
4. 텍스트 중심 본문과 다른 상품 배너를 포함하는 본문을 검증하고 기존 진단 엔진에 순서대로 전달한다.
5. 개인 Chrome 수집기를 사용하지 않은 상태에서 히어로 신청부터 보고서 생성까지 확인한다. 이 확인 전에는 독립 자동화를 완료로 표시하지 않는다.

서비스 계정 활성화나 결제만으로 네이버 수집 성공이 보장되지는 않는다.
